# BuildHub application workspace

Mode: Operate. The user explicitly selected the RonDesignLab Customer Journey CRM reference for the entire existing application. This replaces the previous scoped warm copper visual world while preserving customer branding controls and business behavior.

## Direction contract

THESIS: Distinguish global workspace selection from contextual operational navigation, using a slim icon rail and horizontal pill navigation.

OWN-WORLD: Soft blue-gray canvas, near-white layered surfaces, dark ink, periwinkle selection accents and restrained coral semantics. Rounded modular containers use spacing and tone rather than heavy shadows. Existing bilingual local fonts and BuildHub branding remain.

STORY: Identify the current workspace, choose an existing module, scan its records or details, then use its existing actions. Data, permissions, forms and schedules retain their real owners and behavior.

FIRST VIEWPORT: An 80px desktop rail frames a 78px search/account row and 60px contextual strip. Page headings are light and compact. Operational content occupies a fluid canvas; mobile uses the existing accessible drawer. Dashboards show existing counts and a role-filtered module directory.

FORM: User-pinned reference, implemented directly in Vue. Shared foundations cover all routed families, with targeted project/execution compositions. Workflow connections represent saved schedule order only.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Evidence limits

Browser review uses isolated profiles with external requests blocked. Synthetic employee and schedule fixtures are verification artifacts only. No claim of full live functionality or populated-route visual acceptance follows from these captures. Existing test/build failures and incomplete checks belong in the migration report.
